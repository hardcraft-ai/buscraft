# EU Cyber Resilience Act readiness

BusCraft is built so that a company can take it into a product or a production test system and meet the Cyber
Resilience Act (Regulation (EU) 2024/2847) without first reworking it. This page lists, for each essential requirement in
Annex I of the regulation, what the project does today and what is still planned.

This is an engineering status page, not a declaration of conformity. Whoever places a product built on BusCraft on the
market as a manufacturer makes their own assessment. This page and the release artefacts are meant to make that work
short.

Status: **Done** = in the repository now. **Planned** = before the first release unless noted.

## Part I: security properties of the product

| Requirement (Annex I, Part I) | BusCraft | Status |
|---|---|---|
| No known exploitable vulnerabilities at release | Dependencies checked against public vulnerability databases in CI; a release is not made with open findings | Done (checks), Planned (release gate) |
| Secure by default configuration | No default passwords. Wi-Fi is off until configured, and its settings can only be changed over USB or an encrypted, paired Bluetooth link, never over the network | Done |
| Security updates | Firmware is updated over USB. Signed images and automatic update notices in the client | Planned |
| Protection from unauthorised access | Bluetooth: LE Secure Connections pairing and an encrypted command channel. The TCP port (5025) is an unauthenticated raw socket like other lab instrument interfaces and belongs on a trusted network | Done, limitation documented |
| Confidentiality of stored data | Wi-Fi credentials stored encrypted in flash with a board-unique key. On the RP2040 the key is derivable from the board, so this protects against casual reading, not a determined attacker with the board. Key in one-time-programmable memory on the RP2350 | Done (RP2040), Planned (RP2350) |
| Integrity of software and data | Firmware signing and secure boot on the RP2350; signed client and app binaries | Planned |
| Data minimisation | No telemetry, no cloud service, no accounts. The adapter only carries instrument traffic | Done |
| Availability of essential functions | Hardware watchdog; bus operations time out instead of blocking | Done |
| Minimised attack surface | Network services: TCP 5025 and mDNS only. Bluetooth: one GATT service. Nothing else listens | Done |
| Limit the impact of incidents | Instrument outputs are only changed by explicit commands; instrument skills record safety limits | Planned (skills) |
| Security-relevant logging | Connection and configuration events on the USB console | Planned |
| Secure deletion of data | `++wifi off` erases the stored credentials | Done |

## Part II: vulnerability handling

| Requirement (Annex I, Part II) | BusCraft | Status |
|---|---|---|
| Identify components: SBOM | CycloneDX SBOM generated by CI and attached to every release | Planned |
| Address vulnerabilities without delay, free security updates | [SECURITY.md](../SECURITY.md): fix target 90 days, free updates | Done |
| Regular security testing | Dependency vulnerability checks on every push and nightly | Done |
| Public disclosure of fixed vulnerabilities | GitHub security advisories with CVE identifiers | Done (process) |
| Coordinated vulnerability disclosure policy | [SECURITY.md](../SECURITY.md) | Done |
| Contact address for reports | Private vulnerability reporting on GitHub | Done |
| Secure distribution of updates | Releases from CI on GitHub; checksums and signatures | Planned (signatures) |
