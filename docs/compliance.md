# Security and regulatory compliance

For anyone evaluating BusCraft for a product, a production test system or a lab: what the project has done, what it
is still working on, and where the limits are. Each requirement is listed once per jurisdiction with the same status
words, so the page can be read by a person or checked by a tool.

This is an engineering status page, not legal advice and not a declaration of conformity. Whoever places a product
built on BusCraft on the market makes their own assessment; this page and the release artefacts are meant to make that
work short. Last reviewed: 2026-11-28.

**Status words:** **Done** = in the repository now. **Planned** = committed work, before the first release unless the
row says otherwise. **Product** = the responsibility of whoever sells a finished device. **N/A** = does not apply.

## Known limitations

- **TCP port 5025 is unauthenticated.** It is a raw socket, like the network interfaces of lab instruments, and belongs
  on a trusted network. Bluetooth uses LE Secure Connections pairing and an encrypted command channel.
- **Wi-Fi credentials on the RP2040** are encrypted with a board-unique key that can be derived from the board. This
  stops casual reading of the flash, not an attacker who has the board. The RP2350 build keeps the key in one-time
  programmable memory (planned).
- **Firmware updates are not yet signed.** Anyone with USB access can reflash the adapter.

## European Union: Cyber Resilience Act

Regulation (EU) 2024/2847. Reporting obligations apply from 11 September 2026, the remaining requirements from
11 December 2027. Mapped against the essential requirements of Annex I.

### Annex I, Part I: security properties of the product

| Requirement | BusCraft | Status |
|---|---|---|
| No known exploitable vulnerabilities at release | Dependencies checked against public vulnerability databases in CI; releases are not made with open findings | Done (checks), Planned (release gate) |
| Secure by default configuration | No default passwords. Wi-Fi is off until configured, and its settings can only be changed over USB or an encrypted, paired Bluetooth link, never over the network | Done |
| Security updates | Firmware updated over USB. Signed images and update notices in the client | Done (updates), Planned (signing, notices) |
| Protection from unauthorised access | Bluetooth pairing and encryption; TCP port unauthenticated (see limitations) | Done, limitation documented |
| Confidentiality of stored data | Wi-Fi credentials encrypted in flash (see limitations) | Done (RP2040), Planned (RP2350) |
| Integrity of software and data | Firmware signing and secure boot on the RP2350; signed client and app binaries | Planned |
| Data minimisation | No telemetry, no cloud service, no accounts. The adapter only carries instrument traffic | Done |
| Availability of essential functions | Hardware watchdog; bus operations time out instead of blocking | Done |
| Minimised attack surface | Network: TCP 5025 and mDNS only. Bluetooth: one GATT service. Nothing else listens | Done |
| Limit the impact of incidents | Instrument outputs change only on explicit commands; instrument skills record safety limits | Planned (skills) |
| Security-relevant logging | Connection and configuration events on the USB console | Planned |
| Secure deletion of data | `++wifi off` erases the stored credentials | Done |

## United States

There is no single federal law like the CRA. The requirements below are the ones a buyer or a product team usually asks
about.

| Requirement | What it asks | BusCraft | Status |
|---|---|---|---|
| California SB-327, Oregon HB 2395 (connected devices) | A unique password per device, or credentials set by the user before first use | No default passwords; credentials only set by the user over USB or paired Bluetooth | Done |
| NIST SSDF (SP 800-218), CISA secure software self-attestation | Secure development practices, attested by suppliers of software to federal agencies; widely reused by companies | See the SSDF table below | Done / Planned |
| SBOM minimum elements (NTIA, CISA) | Supplier, component, version, unique identifier, dependency relationship, author, timestamp | CycloneDX SBOM per release with these fields; VEX statements for CVEs that do not affect BusCraft | Planned |
| FCC Part 15 (radio and emissions) | Equipment authorisation for radio transmitters; Part 15B for digital devices | The Pico W is FCC certified. Own boards use a radio module with modular approval. Finished devices: Part 15B | Product |
| US Cyber Trust Mark (FCC, voluntary) | IoT security baseline based on NISTIR 8425, close to CRA Annex I Part I | The Annex I mapping above covers the baseline. The label applies to a finished product | Product |
| Export controls (EAR) | Classification of items with encryption | Published open-source code using standard cryptography (AES, Mbed TLS) is not subject to the EAR. Finished devices: mass market classification | N/A (source), Product (devices) |
